# DATA HANDLING

Create a server-side service/module specifically for Google Sheets.

The React components should NOT know how Google Sheets works.

For example:

UI
→ onboarding submission service
→ repository/data layer
→ Google Sheets

Keep the storage implementation separated enough that Google Sheets can later be replaced with the CRM database without rebuilding the onboarding UI.

Create a normalized TypeScript type/schema for the onboarding submission.

Validate submissions server-side before writing them.

Reject:

* Missing required fields
* Invalid email
* Invalid enum values
* Impossible numeric values
* Malformed multi-select arrays
* Invalid acknowledgement state
* Unexpected fields where appropriate

Do not trust client-side validation alone.

Generate a unique `submission_id` for every successful onboarding.

Add a `schema_version` such as:

`onboarding_v1`

This is important because the form may evolve over time.

Store timestamps server-side.

---

# MULTI-SELECT STORAGE

Do not create messy human-readable values that will be difficult to migrate later.

Normalize arrays consistently.

For Google Sheets, use a predictable serialized format such as JSON arrays.

Example:

["Monday","Wednesday","Friday"]

instead of:

Monday, Wednesday & Friday

The same principle applies to:

* equipment_access
* secondary_goals
* progress_methods
* feedback_preference
* available_days

# SECURITY

Because this contains private client and health-related information, do not treat Google Sheets like a public database.

Requirements:

* Google credentials must remain server-side.
* Do not expose Sheet IDs unnecessarily in the browser.
* Do not make the spreadsheet publicly editable.
* Do not make the spreadsheet publicly viewable.
* Sanitize and validate submissions.
* Do not log sensitive form answers unnecessarily.
* Protect coach-facing routes.
* Never put service-account credentials into client-side `NEXT_PUBLIC_*` variables.
* Use `.env.local` for local configuration and deployment environment variables in production.
* Ensure `.env.local` is gitignored.

If authentication for the temporary coach dashboard would substantially complicate the build, prioritize protecting the route with the simplest secure solution rather than building a full user/account system.
